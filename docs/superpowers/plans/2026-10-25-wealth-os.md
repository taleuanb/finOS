# Wealth OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Application web personnelle mobile-first, branchée sur Notion, qui valorise le patrimoine (multi-devises EUR/MAD/USD), suit les métaux, calcule le budget type et pilote un plan d'épargne mensuel avec cumul de l'argent non investi.

**Architecture:** Next.js (App Router) sur Vercel. Notion est la seule base de données. Le code est découpé en `domain/` (calculs purs), `prices/` (cours et taux de change), `notion/` (dépôt de données), `sync/` (synchro quotidienne), `lib/load.ts` (assemblage du modèle de vue) et des écrans qui reçoivent un objet `Dashboard`. Une interface `Repo` avec une implémentation en mémoire (`FakeRepo`) et une donnée d'exemple `Dashboard` sont figées dans la tâche 1. Toutes les autres tâches s'appuient sur ces contrats et peuvent donc avancer en parallèle.

**Tech Stack:** Node 20+, Next.js 15 (App Router), TypeScript strict, Tailwind CSS 4, Recharts 2, `@notionhq/client` (dernière v5), Vitest + Testing Library (jsdom), Playwright (pré-installé, `require('playwright')`, ne pas réinstaller).

**Spec:** `docs/superpowers/specs/2026-10-25-wealth-os-design.md` (lire avant toute tâche). Maquettes de référence : https://claude.ai/artifact/3vmbwEfwJnwvuoN24qPqas

## Global Constraints

- Langue de l'interface : français. Montants au format `fr-FR` avec des **espaces normales** (remplacer ` ` et ` `), par exemple `1 234 €`, `160 000 MAD`, `12 $`.
- Devise de référence : **EUR**. Taux exprimés en « unités par 1 EUR » (`fx.MAD = 10.85` signifie 1 € = 10,85 MAD). Devises d'actif : `EUR | MAD | USD`. Devises de cotation : en plus, `GBP`.
- Les dates sont toujours calculées dans le fuseau **Europe/Paris** (instantané du jour, mois du plan).
- Couleurs (spec §7) : fond `#F4F5F7`, carte `#FFFFFF`, bordure `#E8E9ED`, texte `#111318`, texte secondaire `#5F6673`, accent `#F4B183`, courbe `#EE8A3C`, gain `#137A3A` sur `#E3F5E9`, perte `#B42318` sur `#FDECEC`. Police Inter. Cibles tactiles ≥ 44 px.
- Mise en page mobile-first : colonne de 390 px de référence, centrée avec `max-width: 480px` sur grand écran, menu du bas à 5 onglets : Synthèse `/`, Patrimoine `/patrimoine`, Budget `/budget`, Épargne `/epargne`, Métaux `/metaux`.
- Notion : au plus 3 requêtes/s ; nouvelle tentative sur une erreur 429 en respectant `Retry-After`, sinon délai croissant 1 s, 2 s, 4 s (3 tentatives).
- Variables d'environnement (jamais de valeur dans le code) : `NOTION_TOKEN`, `NOTION_PARENT_PAGE_ID`, `NOTION_DB_ASSETS`, `NOTION_DB_MOVEMENTS`, `NOTION_DB_DEBTS`, `NOTION_DB_BUDGET`, `NOTION_DB_STRATEGY`, `NOTION_DB_PLAN`, `NOTION_DB_HISTORY`, `APP_PASSWORD`, `SESSION_SECRET`, `CRON_SECRET`.
- Cache des lectures : tag `notion`, `revalidate: 600` ; `revalidateTag('notion')` après chaque synchro ou écriture.
- Aucune écriture dans Notion sans action explicite de l'utilisateur, sauf les champs « (script) » écrits par la synchro (spec §4).
- Commandes : `npx vitest run <fichier>` pour les tests unitaires ; `npm run typecheck` (`tsc --noEmit`) doit passer à la fin de chaque tâche.

## Review Focus

1. **Tickers cotés en pence (`GBp`, ex. `CSPX.L`)** : un prix renvoyé en pence doit être divisé par 100 et converti depuis le GBP, sinon la valeur est fausse d'un facteur 100. Testé en T8 et T2.
2. **Échec partiel au milieu de la synchro** (une source ou une écriture Notion en échec) : les autres actifs sont mis à jour, l'instantané est quand même écrit avec `partial: true`, et le rapport liste l'erreur ; jamais d'exception non rattrapée. Testé en T14.
3. **Classe ciblée sans actif principal, ou actif principal archivé** : `allocate` doit lever une `AllocationError` lisible (« Aucun actif principal pour la classe Crypto »), que l'écran Épargne affiche au lieu de planter. Testé en T4 et T21.
4. **Frontières de jour et de mois** : le cron tourne à 05:00 UTC ; à 23:30 UTC le 31 octobre, il est déjà le 1er novembre à Paris. Le mois du plan et la date d'instantané suivent Paris. Testé en T1 (`parisDate`, `parisMonth`) et T5.
5. **Mode « masquer les montants »** : aucun montant ne doit fuiter (axes, infobulles, titres de graphiques, `aria-label`). Testé en T13.

```
fixed = actifs non archivés avec fixedMonthly → montant = fixedMonthly × months (plafonné à M)
R = M − Σ fixed ; classes = clés de strategy.targets
valeur(classe) = Σ valueEur des actifs non archivés de la classe + Σ fixed attribués à la classe
base = Σ valeur(classes) − Σ fixed attribués + M          // la base inclut M une seule fois
écart(c) = max(0, base × cible(c) − valeur(c))
si Σ écarts ≥ R : part(c) = R × écart(c) / Σ écarts
sinon : part(c) = écart(c) + (R − Σ écarts) × cible(c) / Σ cibles
classe Métaux : or = part × zone.goldShare (zone = zoneFor(ratio) ou neutralZone si ratio null) ; argent = reste ; origin 'signal'
autres : actif principal, origin 'cible'
arrondi à l'euro par la méthode du plus grand reste pour garder Σ = M ; supprimer les lignes à 0
```

### Tasks 17 à 21 : Écrans

Conventions communes :
- `src/app/<route>/page.tsx` est un composant serveur : `const d = await getDashboard()`, puis `<XView data={d} />`.
- `XView` est dans `src/views/XView.tsx` et ne reçoit que `Dashboard` (et des actions serveur en props), ce qui permet de le tester avec `fixtureDashboard`.
- Les écritures passent par des **server actions** dans `src/app/<route>/actions.ts`. Chacune utilise `getRepo()`, appelle `revalidateTag('notion')` et renvoie `{ ok: true } | { ok: false; error: string }`. En cas d'erreur, le formulaire garde sa saisie et affiche l'erreur.
- Si `d.stale` vaut `true`, un bandeau affiche « Données du <date> ».
- Consumes commun : `Dashboard`, `fixtureDashboard`, `getDashboard` (T1) ; kit UI (T13) ; `getRepo` (T1).
